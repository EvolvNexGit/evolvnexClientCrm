<objective>
A saved clinic bill prints as a body-only receipt through the Phase 2 print mechanism, with the receipt number, items, totals and payment line, from the billing tab (BILL-04; decisions D-07, D-08).

Purpose: the receptionist hands the patient a receipt on pre-printed letterhead; it must match the stored bill and use the clinic's own margins, and it must never print onto the letterhead with default margins because the settings failed to load.
Output: `fetchClinicBillById`, the import-free payment label helper, `ClinicReceiptPrint`, the `useClinicReceiptPrint` hook and Print wired into the billing tab with its settings states.

Tracer note: Task 1 is the tracer: Print on a bill row, through the by-id re-fetch, the hook, PrintSheet and the receipt body, to the print dialog. Task 2 expands to the settings states and stale-job handling in the tab.

**Prerequisites:** plan 03-02 (tab, queries, types) and the Phase 2 print stack (PrintSheet, usePrintJob, usePrintSettings, the global print CSS) which this plan reuses unchanged. Plan 03-05 reuses `useClinicReceiptPrint` for the print button after a bill is created.

Out of scope (D-14): WhatsApp receipt sending, tax or GST lines, a clinic header or footer on the receipt.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| database bill and patient fields -> printed sheet | Names and product names are rendered into a document that goes to paper |
| browser print job -> printer | A leftover job could print a previous patient's receipt |
| print settings -> letterhead | Margins decide where text lands on pre-printed paper |

## STRIDE Threat Register

Threat IDs are unique within the phase (T-03-01 to T-03-34 across plans 03-01 to 03-07).

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-----------|-----------------|
| T-03-20 | Tampering | script or markup injection through patient or product names into the receipt | medium | mitigate | all dynamic values render as React text nodes; static gate forbids raw HTML injection in the receipt file |
| T-03-21 | Information Disclosure | a leftover print job or a stale payload printing another patient's receipt | medium | mitigate | the payload is the by-id re-fetched bill; usePrintJob clears on afterprint and after 60 s; the tab clears the job when the filter changes; client scoping on the fetch |
| T-03-22 | Tampering | receipt printed onto the letterhead with default margins because settings failed to load | low | mitigate | every Print button is disabled until printSettings.ready; a failed load shows an error with Retry |
| T-03-23 | Information Disclosure | receipt exposing clinical data (vitals, findings) on a billing document | low | mitigate | the receipt component takes only a ClinicBillRecord, which has no consultation content; static gate forbids clinical field names in the print files |
| T-03-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this phase (D-13); `git diff --name-only -- package.json package-lock.json` must be empty |

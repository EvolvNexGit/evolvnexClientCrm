<objective>
The doctor client gets a billing tab that lists its clinic bills, filters to the unpaid ones and marks a bill paid with a payment mode (BILL-01 registration, BILL-02 payment fields in use, BILL-04 unpaid list; decisions D-04, D-05, D-06, D-13).

Purpose: staff need one place for outstanding bills before they can create or print any. The tab is registered through the full AGENTS.md contract but stays invisible everywhere until migration C (plan 03-06) adds the 015 access row, so shipping this code changes nothing for any tenant on its own.
Output: clinic billing types, a clinic-only query module, a paged hook, the `doctor-billing` tab and its registration in the four registry files.

Tracer note: Task 1 is the tracer: one read path from live `bills` through a clinic-only select, a mapper, a paged hook and the tab screen. Task 2 makes it reachable through the registration contract. Task 3 expands to the Mark paid action. Creating bills (plan 03-05), receipts (03-04) and the cafe exclusion guards (03-03) come later.

**Prerequisite:** plan 03-01 Task 3 reported verified (migrations A and B live). The select in this plan lists `payment_status`, `payment_mode`, `consultation_id` and `appointment_id` and the list filters on the Clinic order source; running it against a database without them fails the clinic list.

Out of scope (D-05, D-14): void or cancel, refunds, partial payments, insurance, tax invoices, per-line price edits.
</objective>

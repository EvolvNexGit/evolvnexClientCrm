<objective>
Clinic bills never appear as active orders, never beep or push, and never enter cafe numbers, while the doctor's own summary counts paid clinic revenue and shows unpaid bills as pending (BILL-05; decisions D-09, D-12).

Purpose: ROADMAP criterion 3 says a final status keeps Clinic bills out of active orders and alerts, but only the list path honors DELIVERED: the realtime handler has no source check and the push route sends for every non-POS source. Code guards are required on all four paths, and the doctor summary reads bills through the same shared fetch, so excluding Clinic by default would silently zero the doctor's revenue unless it opts in.
Output: the shared predicate, guards on the four paths (E1 to E4), the opt-in on the shared fetch, and the doctor summary revenue and pending rules.

Tracer note: Task 1 is the tracer: the predicate flows through the shared fetches to every consumer (orders list, alert hydrate and poll, cafe summary). Task 2 closes the realtime and push paths. Task 3 expands to the doctor summary opt-in and its paid-only rule.

**Prerequisite:** plans 03-01 and 03-02 verified. This plan ships before any Clinic bill can be created from the UI (plan 03-05), so the guards are live first.

Out of scope (D-09, D-14): patient totalSpent, the Transaction tab, a payment-status column in the shared select, void and refund handling.
</objective>

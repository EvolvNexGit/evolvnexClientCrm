<objective>
Give a patient (a `customers` row) four nullable clinical fields and make them editable in the existing customer add/edit modal for clinic clients only (PAT-01, decisions D-09, D-10, D-11).

Purpose: allergies and chronic conditions must be recorded before the patient profile drawer (plan 01-05) can show them prominently.
Output: one additive migration file, extended customer types and queries, and four gated inputs in `customer-table.tsx`.

**Deployment ordering (blocking, handled in plan 01-07 Task 1):** `CUSTOMER_SELECT` will reference the new columns. If this code reaches an environment before the migration is applied to that database, EVERY customers query fails for EVERY tenant (PostgREST unknown column). The repo migration is a source-of-truth document only (D-14); the user applies it to live by hand before any deploy or browser verification.

Tracer note: Task 1 threads the `allergies` field through every layer (migration, type, select, map, create, update, gated form input); Task 2 expands to the other three fields.
</objective>

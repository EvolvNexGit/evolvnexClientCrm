## Flagged assumptions

- **A-01 time storage:** appointment `start_time` and `end_time` are assumed to be time-only strings (HH:MM or HH:MM:SS) written by the add/edit form, with legacy ISO timestamps possible from other writers. `clockToMinutes` reads time-only values as wall-clock (the same value the edit form shows and the slot click writes back) and converts ISO timestamps to IST minutes. The existing list view formats time-only values through an IST conversion in `time-utils.ts`; if live data is time-only, the list may display a different clock time than the calendar. That list behaviour is NOT changed here (pure refactor, D-06); the executor records the live column type and one sample in the SUMMARY so a human can decide on a follow-up.
- **Concurrency edge (APPT-01):** no realtime and no DB constraint this phase; see the backstop truth.

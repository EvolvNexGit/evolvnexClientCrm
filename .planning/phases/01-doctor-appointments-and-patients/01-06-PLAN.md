<objective>
Warn the receptionist when a booking or move overlaps another appointment for the same staff on the same date (APPT-02, decision D-04). The warning is advisory: it never blocks saving, and there is no database constraint in this phase (D-08).

Purpose: double bookings should be a conscious choice, not an accident.
Output: a pure conflict function, a non-blocking banner in the add, edit and reschedule modal, and an amber ring on overlapping calendar cards.

Tracer note: Task 1 is the tracer (pure function plus modal banner, end to end). Task 2 adds the calendar highlight.

**Interpretation to confirm:** D-04 says to check client-side "against the loaded range". The default List view loads no range, and the modal's date can change, so this plan loads the modal date's appointments through the same `useAppointmentsRange` hook (one small request per date) and checks against those. Still client-side, still advisory, no new endpoint.
</objective>

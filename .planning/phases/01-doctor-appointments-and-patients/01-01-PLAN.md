<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form -> query layer | Staff-entered appointment fields and a clientId from the tab prop cross into Supabase writes |
| query layer -> Supabase (anon key + RLS) | PostgREST requests; own-client RLS via `current_client_id()` is the server-side enforcement |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | updateAppointment / setAppointmentStatus (previously unscoped direct writes) | high | mitigate | Both filter `.eq("client_id", clientId)` and `.eq("id", appointmentId)`; select of id plus a zero-row check throws "Appointment not found." so a foreign or stale id is a visible failure; RLS stays the backstop |
| T-01-02 | Elevation of Privilege | createAppointment tenant id | high | mitigate | client_id is written after the payload spread from the clientId argument, which the tab sources from its prop (derived from the authenticated user mapping), never from form state or URL |
| T-01-03 | Denial of Service | fetchAppointmentsRange unbounded read | medium | mitigate | Hard cap `APPOINTMENT_RANGE_MAX = 1000` via range(), date arguments validated against an ISO pattern and ordering before the request |
| T-01-04 | Information Disclosure | formatSupabaseError surfaces PostgREST message/details/hint in the UI | low | accept | Authenticated staff of the same tenant only; text is already used by other tabs; no stack traces leave the browser |
| T-01-05 | Repudiation | No audit trail for appointment edits | low | accept | Audit log is deferred (CLIN-02, out of scope for this milestone phase) |
| T-01-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs in this phase (D-16); `git diff --name-only -- package.json package-lock.json` must be empty; no package legitimacy audit required |
</threat_model>
